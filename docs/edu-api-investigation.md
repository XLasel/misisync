# Исследование API расписания МИСИС

**Текущий итог:** полный `edu.misis.ru3.har` содержит исходники страницы. Время на сайте задано фиксированным массивом, а расхождение количества занятий объясняется объединением записей одного предмета в ячейке с показом типа первой записи. Это не алгоритм удаления дублей по ID. Ниже сохранён ход проверки; окончательные уточнения находятся в разделе «Полный HAR и исходники страницы».

Дата анализа: 08.09.2026. Источник: предоставленный пользователем `edu.misis.ru.har`, группы МПИ-26-1-1 и МПИ-26-1-2. Сам HAR в репозиторий не добавлен. Аналитические запросы сторонних сервисов для исследования не использовались.

## Подтверждённый контракт

Все четыре университетских запроса в записи: `POST https://edu.misis.ru/schedule`, Content-Type запроса `text/plain;charset=UTF-8`, ответ HTTP 200 с JSON-RPC 2.0.

| Метод | params | Назначение |
| --- | --- | --- |
| `ScheduleService.getFilials` | `[]` | Справочник филиалов |
| `ScheduleService.getFillialInfo` | `["MOSCOW"]` | Справочники Москвы; написание Fillial сохранено из запроса |
| `ScheduleService.getSchedule` | Одна строка параметров в массиве | Расписание группы за диапазон дат |

Пример записанного тела запроса, без персональных заголовков:

```json
{
  "jsonrpc": "2.0",
  "method": "ScheduleService.getSchedule",
  "params": ["begin_date=2026-09-07&end_date=2026-09-12&ed_group_id=3872519&show_ceiltail=true&show_sunday=false"],
  "id": 1
}
```

МПИ-26-1-1 имеет ID `3872519`, МПИ-26-1-2 — `6860689`. Это две отдельные группы. Окончания их названий нельзя интерпретировать как номера подгрупп одной группы.

`getFillialInfo` вернул 470 групп, 641 аудиторию, 1076 предметов, 814 преподавателей и 7 типов занятий. Группы содержат `id`, `name`, `subgroups`; явных института и уровня образования в этих записях нет. Аудитории содержат сведения о корпусе.

Ответ расписания имеет структуру `result.lists[].rows[].cells[].lessons[]`. На уровне недели есть `week_number`, строки — `lesson_date` и `day_number`, ячейки — номер пары и время звонков. Занятие содержит название и ID предмета, тип, преподавателей, аудитории, группы/подгруппы, `lesson_index`, `in_ceiling`, индивидуальное время и списки LMS-ссылок. Наличие полей не означает, что они заполнены.

## Что показали эти две группы

- В каждом ответе 9 вхождений занятий в ячейки и 8 различных `lesson_index`.
- Практика по защите информации с одним `lesson_index` встречается в шестой и седьмой ячейках понедельника. Это нельзя автоматически считать случайным дублем или доказательством продолжительности: семантика ещё не проверена.
- У всех 18 вхождений `in_ceiling=true`, `lesson_start=null`, `lesson_end=null`. Время соответствующих ячеек тоже `null`, хотя в пустых ячейках других дней время звонков заполнено. Первоначально восстановление времени оставалось неподтверждённым; последующая сверка со скриншотами описана ниже.
- Даты строк — 07–12.09.2026, `week_number=37`. Это совпадает с календарной ISO-неделей; нельзя считать поле номером учебной недели или напрямую переводить в числитель/знаменатель.
- Все поля подгруппы у занятий равны `null`. В справочнике у каждой из двух групп есть подгруппа с номером 1 и ID `11`. Один и тот же ID встречается у разных групп, поэтому глобальную уникальность ID подгруппы предполагать нельзя.
- Во всём каталоге: 130 групп с подгруппой 1, 211 с подгруппами 1/2, 18 с 1/2/3 и 111 без списка подгрупп. Фильтр подгрупп технически возможен, но пустое поле занятия не даёт права приписывать его конкретной подгруппе.
- Две записи английского имеют разные `lesson_index` для разных групп; многие другие ID занятий совпадают между группами. При хранении нужна явная связь занятий с группами.
- Воскресенье исключено параметром `show_sunday=false`. По этой записи нельзя заключить, что воскресных занятий нет.

## Сравнение с текущей SQLite из Excel

Сравнение выполнено с локальным снимком на момент анализа, по точному имени группы: 491 группа в Excel, 470 в HAR, 455 общих, 36 только в Excel и 15 только в HAR. Различие состава не позволяет считать API полной заменой всех Excel-файлов без дополнительной проверки.

Для каждой из двух групп в SQLite есть 17 записей шаблона недель, включая время и пометки подгрупп. Это не сопоставимо напрямую с 9 ячейками одной календарной недели. Например, для понедельника Excel содержит время 16:20–17:55 для спецглав математики, тогда как API оставляет время пустым. Причина различий и смысл `in_ceiling` не установлены.

## Проверки перед подключением

1. Повторить чтение справочника и одной группы в чистой сессии без cookies и Authorization. Очищенный HAR исключает эти заголовки, поэтому сам по себе не подтверждает анонимный доступ. В текущем исследовании сетевое воспроизведение не выполнялось из-за ранее полученного ограничения доступа встроенного браузера.
2. После сверки со скриншотами проверить код преобразования ответа в таблицу: как выбирается ячейка для повторяющегося `lesson_index` и что означает `in_ceiling` / `show_ceiltail`. Время на странице подтверждено, правило обработки повторов пока нет.
3. Записать следующую неделю для одной группы, чтобы проверить изменение дат и занятий. Одна неделя не подтверждает корректность замен, отмен и исключений.
4. Проверить воскресенье и группу с фактически разделёнными подгруппами; наличие справочника подгрупп не гарантирует заполнение соответствующих полей занятия.
5. Выяснить покрытие институтов и диапазонов дат. В записанных ответах расписания нет ETag / Last-Modified / Cache-Control; поддержка условных запросов, лимиты и максимальный диапазон не установлены.

Адаптер должен проверять JSON-RPC `error` даже при HTTP 200, полноту каждого выбранного диапазона и сохранять последний успешный снимок при сетевых или структурных ошибках. Пустая неделя может быть корректным ответом и должна отличаться от ошибки загрузки. Необходимо сохранять даты и происхождение данных; импорт календарной недели в существующий бесконечно повторяющийся шаблон недопустим.

## Сверка с двумя скриншотами от 08.09.2026

На обоих скриншотах показана неделя 07–12.09.2026, выбраны соответственно МПИ-26-1-1 и МПИ-26-1-2. В предоставленном по тому же пути HAR по-прежнему только два запроса расписания за этот диапазон; время запросов 15:13:45 и 15:13:57 UTC. Запросов следующей недели и исходного JavaScript страницы в файле нет.

Скриншоты уточняют первоначальный вывод: `null` во времени самого занятия не означает отсутствия времени на странице. В каждом ответе можно собрать непротиворечивое расписание звонков из других ячеек по ключу `(bell_subset_id, bell_id, bell_number)`. Все 7 номеров пар имеют ровно один заполненный интервал, и все 9 вхождений занятий сопоставляются с таким ключом.

| Пара | Время в ответе для того же ключа звонка | Подтверждение на скриншоте |
| --- | --- | --- |
| 1 | 09:00–10:35 | Строка не показана |
| 2 | 10:50–12:25 | Лекция по компьютерному зрению, суббота |
| 3 | 12:40–14:15 | Практика по компьютерному зрению, суббота |
| 4 | 14:30–16:05 | Пустая строка |
| 5 | 16:20–17:55 | Спецглавы математики, понедельник; английский, четверг |
| 6 | 18:00–19:25 | Лекция по защите информации, понедельник; системы хранения, среда; квантовые вычисления, четверг |
| 7 | 19:35–21:00 | Практика по защите информации, понедельник |

Такое восстановление соответствует показанному времени для этих двух примеров. Это ещё не доказательство универсального алгоритма для всех групп и нестандартных занятий. При конфликтующих интервалах нельзя произвольно выбирать один.

На каждом скриншоте видно 8 занятий. Практика по защите информации показана только в 19:35, хотя HAR содержит полностью одинаковый объект этой практики и в шестой, и в седьмой ячейках. Простое разворачивание всех ячеек даст лишнюю практику в 18:00. Удаление повторов с сохранением первого вхождения оставит её в неверное время. Правило «всегда брать последнее» также не подтверждено. Фильтр `in_ceiling=true/false` не решает вопрос: у всех записанных занятий значение одинаковое.

Следующий необходимый материал для проверки преобразования — HAR со всеми типами запросов (`All`), записанный с перезагрузкой страницы, чтобы в нём присутствовали HTML и JavaScript. В той же записи можно переключить одну группу на следующую неделю. До проверки алгоритма фронтенда API не включён в рабочий импорт.

## Следующая неделя: `edu.misis.ru1.har`

Вторая запись содержит запросы МПИ-26-1-1 (`3872519`) за 07–12.09.2026 и 14–19.09.2026. В ней 7 сетевых записей, включая 4 университетских JSON-RPC запроса. HTML и JavaScript страницы отсутствуют. Исходный HAR в репозиторий не добавлен.

На 14–19 сентября сервер вернул `week_number=38`, 9 вхождений и 9 различных `lesson_index`. Расписание отличается от предыдущей недели:

- Спецглавы математики в понедельник меняются с практики на лекцию.
- В понедельник вместо защиты информации появляются лекция и практика по современным методам решения инженерных задач.
- В среду есть лабораторная и лекция по системам хранения и обработки данных.
- Квантовые вычисления в четверг меняются с практики на лекцию.
- В пятницу появляются лекция и практика по организации и технологии научных исследований и педагогической деятельности.
- Субботнее компьютерное зрение в ответе следующей недели отсутствует.

У лабораторной 16 сентября поле `ed_groups[].subgroup_id="11"`, `subgroup_number=1`. Это первое подтверждённое в предоставленных ответах занятие с явно заданной подгруппой. У остальных восьми вхождений поля подгруппы пустые. Для фильтра 1 следует сохранять как явно относящиеся к нему занятия, так и занятия без пометки; отсутствие пометки не доказывает общую принадлежность.

У всех девяти занятий снова `in_ceiling=true`, собственное время и время занятых ячеек пустое. Все ячейки сопоставляются с единственными интервалами звонков того же ключа в других днях ответа. Лабораторная и лекция по системам хранения занимают одну ячейку; аналогично совпадают ячейки двух типов научно-исследовательского занятия в пятницу. Это разные ID, поэтому удалять их как дубли только по дате и времени нельзя. Их отображение на странице следующей недели ещё не проверено.

Английский 10 и 17 сентября имеет одинаковый `lesson_index`. Следовательно, этот ID не является уникальным идентификатором отдельного календарного события. Ключ хранения должен учитывать как минимум дату и принадлежность группе; отдельным вопросом остаётся выбор ячейки при повторе ID в пределах одного дня.

Подтверждён выбор календарного диапазона и изменение состава занятий между двумя неделями. Работа с заменами, отменами, доступ без сессии и алгоритм устранения повторов по-прежнему не подтверждены. Эти наблюдения не дают основания автоматически заменять текущий источник или интерпретировать номер ISO-недели как учебную чётность.

## Полный HAR и исходники страницы

Актуальный файл `edu.misis.ru3.har` содержит 71 запрос и около 6,2 МБ данных, включая HTML, JavaScript и четыре недели МПИ-26-1-1. Исследование кода выполнено чтением предоставленных текстов без их запуска и без сетевых обращений. HAR и сторонние исходники в репозиторий не копировались.

Основной проверенный файл: `/_app/immutable/nodes/4.BdqK_qZf.js`, SHA-256 текста UTF-8 `b439faf7afff7e5c12fe4a0426aaf01d4a9adf49ca028c2eec79dd1e3d0b92f1`. Номера строк ниже относятся к тексту этого ресурса в HAR.

### Время и диапазон

В строке 7342 начинается фиксированный массив `times` из семи пар, 09:00–10:35 … 19:35–21:00. Таблица сопоставляет записи по номеру пары. Предыдущее наблюдение о возможности собрать интервалы из других ячеек было верным для этих ответов, но описывало возможный способ импорта, а не фактическую реализацию университетского сайта.

`getSchedule` рассчитывает начало ISO-недели по выбранной дате, конец через пять дней и передаёт `begin_date`, `end_date`, выбранные идентификаторы группы/преподавателя/аудитории, `show_ceiltail=true`, `show_sunday=false`. Переходы меняют выбранную дату на семь дней. В просмотренном модуле нет обращений к `in_ceiling` и `lesson_index`: эти поля не объясняют поведение таблицы.

### Почему исчезает второй тип занятия

В обеих реализациях таблицы (условия на строках 6361 и 6880) проверяется, совпадает ли `subject_id` у первых двух занятий ячейки. При совпадении сайт отображает один блок предмета, берёт название и тип из `lessons[0]` (например, строка 6484), а сведения о преподавателях/аудиториях частично объединяет. Сравнение типов и ID занятий не является условием этого объединения.

Если первые два предмета различаются, используется отдельная ветка вывода списка. Поэтому трактовать видимую таблицу как точный перечень всех объектов API нельзя; алгоритм может скрыть различия типов, а не только случайные дубли.

Это полностью объясняет проверенные расхождения:

| Неделя | Вхождения в API | Блоки предметов по правилу сайта | Что объединяется |
| --- | --- | --- | --- |
| 07–12.09 | 9 | 8 | Защита информации: лекция и практика в 18:00; виден тип лекции |
| 14–19.09 | 9 | 7 | Системы хранения: лабораторная и лекция; научные исследования: лекция и практика |
| 21–26.09 | 9 | 8 | Как на первой неделе |
| 28.09–03.10 | 9 | 7 | Как на второй неделе |

Подсчёт воспроизведён локально на всех четырёх JSON-ответах и согласуется с предоставленными скриншотами. Практика по защите информации в 19:35 остаётся видимой, потому что в этой ячейке она единственная. Сайт не выбирает последнюю ячейку по `lesson_index`: он объединяет две записи в предыдущей ячейке. Истинная причина повторения ID на стороне серверных данных всё ещё не установлена.

### Текущее решение Misisync

Исследование выше фиксирует наблюдения по HAR на момент подключения. Переход выполнен: единственный рабочий источник — JSON-RPC `edu.misis.ru`, без Excel и постоянной базы. Серверный транспорт не передаёт пользовательские cookies или API-ключ; расписание загружается по выбранной группе и датам, с ограниченным кэшем в памяти и возвратом последнего ответа при временном сбое.

- Сохраняются различия типов занятий, преподавателей и явно указанных подгрупп.
- Время берётся из занятия, затем ячейки, затем непротиворечивой сетки звонков. Фиксированный запасной интервал применяется только к проверенной московской сетке.
- Повтор ID в соседних парах сам по себе допустим для сдвоенного занятия; предупреждение появляется при неоднозначном сочетании нескольких вариантов предмета.
- «Запись в источнике» содержит только разрешённые поля расписания. Дополнительные поля upstream, LMS-ссылки и сведения других групп не публикуются.
