# Исследование API расписания МИСИС

Дата анализа: 08.09.2026. Источник: предоставленный пользователем `edu.misis.ru.har`, группы МПИ-26-1-1 и МПИ-26-1-2. Сам HAR в репозиторий не добавлен. Аналитические запросы сторонних сервисов для исследования не использовались.

## Подтверждённый контракт

Все четыре университетских запроса в записи: `POST https://edu.misis.ru/schedule`, Content-Type запроса `text/plain;charset=UTF-8`, ответ HTTP 200 с JSON-RPC 2.0.

| Метод | params | Назначение |
| --- | --- | --- |
| `ScheduleService.getFilials` | `[]` | Справочник филиалов |
| `ScheduleService.getFillialInfo` | `["MOSCOW"]` | Справочники Москвы; написание Fillial сохранено из запроса |
| `ScheduleService.getSchedule` | Одна строка параметров в массиве | Расписание группы за диапазон дат |

Пример записанного тела запроса, без персональных заголовков:

```json
{
  "jsonrpc": "2.0",
  "method": "ScheduleService.getSchedule",
  "params": ["begin_date=2026-09-07&end_date=2026-09-12&ed_group_id=3872519&show_ceiltail=true&show_sunday=false"],
  "id": 1
}
```

МПИ-26-1-1 имеет ID `3872519`, МПИ-26-1-2 — `6860689`. Это две отдельные группы. Окончания их названий нельзя интерпретировать как номера подгрупп одной группы.

`getFillialInfo` вернул 470 групп, 641 аудиторию, 1076 предметов, 814 преподавателей и 7 типов занятий. Группы содержат `id`, `name`, `subgroups`; явных института и уровня образования в этих записях нет. Аудитории содержат сведения о корпусе.

Ответ расписания имеет структуру `result.lists[].rows[].cells[].lessons[]`. На уровне недели есть `week_number`, строки — `lesson_date` и `day_number`, ячейки — номер пары и время звонков. Занятие содержит название и ID предмета, тип, преподавателей, аудитории, группы/подгруппы, `lesson_index`, `in_ceiling`, индивидуальное время и списки LMS-ссылок. Наличие полей не означает, что они заполнены.

## Что показали эти две группы

- В каждом ответе 9 вхождений занятий в ячейки и 8 различных `lesson_index`.
- Практика по защите информации с одним `lesson_index` встречается в шестой и седьмой ячейках понедельника. Это нельзя автоматически считать случайным дублем или доказательством продолжительности: семантика ещё не проверена.
- У всех 18 вхождений `in_ceiling=true`, `lesson_start=null`, `lesson_end=null`. Время соответствующих ячеек тоже `null`, хотя в пустых ячейках других дней время звонков заполнено. Подставлять его как подтверждённое время занятий нельзя.
- Даты строк — 07–12.09.2026, `week_number=37`. Это совпадает с календарной ISO-неделей; нельзя считать поле номером учебной недели или напрямую переводить в числитель/знаменатель.
- Все поля подгруппы у занятий равны `null`. В справочнике у каждой из двух групп есть подгруппа с номером 1 и ID `11`. Один и тот же ID встречается у разных групп, поэтому глобальную уникальность ID подгруппы предполагать нельзя.
- Во всём каталоге: 130 групп с подгруппой 1, 211 с подгруппами 1/2, 18 с 1/2/3 и 111 без списка подгрупп. Фильтр подгрупп технически возможен, но пустое поле занятия не даёт права приписывать его конкретной подгруппе.
- Две записи английского имеют разные `lesson_index` для разных групп; многие другие ID занятий совпадают между группами. При хранении нужна явная связь занятий с группами.
- Воскресенье исключено параметром `show_sunday=false`. По этой записи нельзя заключить, что воскресных занятий нет.

## Сравнение с текущей SQLite из Excel

Сравнение выполнено с локальным снимком на момент анализа, по точному имени группы: 491 группа в Excel, 470 в HAR, 455 общих, 36 только в Excel и 15 только в HAR. Различие состава не позволяет считать API полной заменой всех Excel-файлов без дополнительной проверки.

Для каждой из двух групп в SQLite есть 17 записей шаблона недель, включая время и пометки подгрупп. Это не сопоставимо напрямую с 9 ячейками одной календарной недели. Например, для понедельника Excel содержит время 16:20–17:55 для спецглав математики, тогда как API оставляет время пустым. Причина различий и смысл `in_ceiling` не установлены.

## Проверки перед подключением

1. Повторить чтение справочника и одной группы в чистой сессии без cookies и Authorization. Очищенный HAR исключает эти заголовки, поэтому сам по себе не подтверждает анонимный доступ. В текущем исследовании сетевое воспроизведение не выполнялось из-за ранее полученного ограничения доступа встроенного браузера.
2. Сопоставить видимую страницу университета с ответом: показано ли у этих занятий время, есть ли легенда или настройка для `in_ceiling` / `show_ceiltail`.
3. Записать следующую неделю для одной группы, чтобы проверить изменение дат и занятий. Одна неделя не подтверждает корректность замен, отмен и исключений.
4. Проверить воскресенье и группу с фактически разделёнными подгруппами; наличие справочника подгрупп не гарантирует заполнение соответствующих полей занятия.
5. Выяснить покрытие институтов и диапазонов дат. В записанных ответах расписания нет ETag / Last-Modified / Cache-Control; поддержка условных запросов, лимиты и максимальный диапазон не установлены.

Адаптер должен проверять JSON-RPC `error` даже при HTTP 200, полноту каждого выбранного диапазона и сохранять последний успешный снимок при сетевых или структурных ошибках. Пустая неделя может быть корректным ответом и должна отличаться от ошибки загрузки. Необходимо сохранять даты и происхождение данных; импорт календарной недели в существующий бесконечно повторяющийся шаблон недопустим.
