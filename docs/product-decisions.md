# Решения по UX и источникам

Дата: 08.09.2026.

## Простой основной сценарий

Студент обычно знает название своей группы. Поэтому главный вход — один поиск с подсказками, поддержкой клавиатуры и сохранением последнего выбора. Для поиска достаточно части названия; регистр, пробелы и разные тире нормализуются.

Институт и уровень образования находятся в раскрываемом блоке «Уточнить поиск». Они помогают найти группу, но не являются обязательными шагами. После выбора группы фильтры расписания — неделя и подгруппа — находятся непосредственно над днями.

Институт определяется по названию ссылки на официальный файл. Для прямой ссылки используются известные префиксы файлов МИСИС; неизвестный источник остаётся без классификации. Это принадлежность к опубликованной таблице, а не дополнительная проверка факультета каждого студента. Уровень образования определяется по первой букве кода группы: Б, М, С, А; неизвестные коды не классифицируются. Если источник начнёт публиковать явные значения, следует предпочесть их.

## Подгруппы

- Список доступных подгрупп строится по данным выбранной группы, включая третью подгруппу.
- Выбор 1 включает записи для 1, для 1 и 2, для 1 и 3 и т. п.
- Записи без подгруппы и с нераспознанной пометкой не скрываются. Отсутствие пометки не выдаётся за доказательство занятия для всей группы.
- Полностью одинаковые пары нескольких подгрупп объединяются в карточку; исходные записи остаются раскрываемыми. Разные аудитории, преподаватели, недели и условия объединять нельзя.
- Выбор подгруппы сохраняется отдельно для каждой группы.

## Визуальный характер

Из [бренд-платформы МИСИС](https://misis.ru/university/rebranding/) использована связь через [основную палитру](https://misis.ru/files/-/ee5a62c57a3f677cc056190051163471/palette.jpg): синий `#0541F0`, тёмно-синий `#0A1E64`, голубой `#37EBFF`.

Misisync сохраняет собственный знак M и написание названия. По пожеланию пользователя интерфейс полностью тёмный: фон `#0C1018`, панели `#131B28`, светлые заголовки и приглушённые цветные карточки. Фирменные синий и голубой связывают приложение с университетом; оттенки текста и действий адаптированы для контраста на тёмном фоне. Тёмная схема распространяется на поля, выпадающие списки, состояния ошибок и первоначальный фон страницы. Шрифт приложения — Golos Text с системным запасным вариантом. В интерфейс не перенесён официальный логотип университета; сервис явно обозначен как неофициальный. Цвета типов занятий дополнены текстовыми подписями.

Цель — дать узнаваемую связь с МИСИС, сохранив удобную, спокойную поверхность ежедневного расписания. Крупные рекламные блоки, обязательная регистрация, каскад обязательных фильтров и дополнительные разделы для этого не нужны.

## Прямой API университета: что проверено

[Страница студентов](https://misis.ru/students/) содержит два разных перехода:

1. [Расписание учебных занятий](https://misis.ru/students/schedule/) — прямые ссылки на XLS/XLSX уже присутствуют в HTML; текущий загрузчик использует их.
2. [Единая страница расписания](https://edu.misis.ru/schedule?filial=MOSCOW) — отдельное приложение с JSON-RPC API `POST https://edu.misis.ru/schedule`.

По предоставленным пользователем HAR подтверждены справочник Москвы, расписания двух групп и четыре соседние недели МПИ-26-1-1. Полный HAR содержит код страницы, позволивший объяснить время и объединение занятий. Подробности и воспроизводимые ссылки на строки исходного ресурса — в [исследовании API](edu-api-investigation.md).

Университетский сайт использует фиксированный список времени пар. Если первые два занятия ячейки имеют одинаковый предмет, он показывает тип только первой записи, частично объединяя остальные сведения. Это объясняет расхождения со скриншотами, но не доказывает ошибочность скрытых записей. В Misisync нельзя терять разные типы и подгруппы при таком объединении.

На скриншоте расписание загружено в инкогнито, клиент сайта не задаёт отдельного API-ключа. Серверный доступ без cookies ещё требует проверки при подключении. Встроенный браузер ранее не смог проверить политику доступа; исследование выполнено по предоставленным файлам без обхода ограничения. Дополнительные ручные записи HAR для определения контракта больше не требуются.

API подходит для разработки адаптера расписания по конкретным датам. Потребуются хранение дат и покрытия диапазонов, сохранение исходных вариантов занятий и обозначение неоднозначных повторов. Рабочий импорт пока остаётся на Excel. Его следует сохранить как отдельный резервный режим; автоматическое смешивание двух несопоставленных расписаний может создать ложные дубли или вернуть отменённые занятия.
