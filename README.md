# Misisync

Неофициальное расписание МИСИС: поиск группы, календарные недели, подгруппы.

Python/FastAPI + React / Next.js + Docker Compose. Источник данных — live JSON-RPC `edu.misis.ru` (как официальный сайт): каталог групп кэшируется, расписание запрашивается по выбранной группе и неделям.

Базы данных и Excel-импорта нет. Кэш в памяти сокращает повторные обращения к университету: каталог хранится час, неделя группы — 15 минут. После истечения срока данные обновляются при следующем запросе. Если обновление не удалось, последняя версия доступна ещё до часа с предупреждением и временем её получения. После перезапуска кэш пуст; истории изменений и офлайн-доступа после перезапуска нет.

## Запуск

```sh
cp .env.example .env
docker compose up --build -d
```

Открыть http://localhost:3000. Нужен работающий Docker Engine.

Деплой на Timeweb VPS (nginx в Docker, HTTPS, автодеплой с GitHub): [deploy/README.md](deploy/README.md).

## Настройки

| Переменная | Назначение |
| --- | --- |
| `EDU_API_URL`, `EDU_FILIAL` | JSON-RPC endpoint и филиал (`MOSCOW`) |
| `EDU_GROUPS` | Фильтр имён в каталоге; пусто = все группы филиала |
| `EDU_REQUEST_DELAY_SECONDS` | Пауза перед каждым RPC (по умолчанию 0.25) |
| `EDU_CATALOG_TTL_SECONDS` | TTL кэша списка групп (3600) |
| `EDU_SCHEDULE_TTL_SECONDS` | TTL кэша недели группы (900) |
| `EDU_SCHEDULE_CACHE_MAX_ENTRIES` | Максимум недель в памяти (256) |
| `EDU_STALE_IF_ERROR_SECONDS` | Допустимый срок старых данных после истечения TTL при сбое (3600) |
| `EDU_RETRY_BACKOFF_SECONDS` | Пауза между повторными попытками после сбоя (30) |
| `EDU_MAX_PENDING_REQUESTS` | Максимум различных недель, ожидающих загрузки (64) |
| `EDU_MAX_CONCURRENT_REQUESTS` | Максимум одновременных обращений к университету (4) |
| `SCHEDULE_RATE_LIMIT_PER_MINUTE` | Лимит `/api/schedule` на IP в публичном прокси Next.js (60) |
| `TRUST_PROXY` | Доверять `X-Forwarded-For` от внешнего прокси (по умолчанию `false`) |
| `REQUEST_TIMEOUT_SECONDS`, `MAX_DOWNLOAD_BYTES` | Таймаут и лимит размера ответа |
| `API_BASE` | Адрес бэкенда для прокси Next.js |
| `PORT` | Порт фронтенда локально (3000); в prod наружу смотрит nginx |
| `DOMAIN` | Hostname для nginx / Let's Encrypt (только prod) |

В Compose наружу открыт только Next.js; FastAPI доступен внутри сети контейнеров. Лимит посетителей применяется в Next.js, где виден их IP. Если перед Next.js стоит внешний reverse proxy, включайте `TRUST_PROXY=true` только когда он перезаписывает `X-Forwarded-For`, а прямой доступ к Next.js закрыт. Иначе все посетители этого прокси разделяют один лимит. Кэш и лимиты локальны одному процессу; несколько экземпляров имеют независимое состояние.

Кнопка «Обновить» повторяет запрос к Misisync и учитывает TTL: она не обходит кэш. В блоке «Данные расписания» показано время последнего успешного получения расписания у университета; для нескольких недель берётся самое раннее время.

## Фронтенд

Next.js App Router + React + TypeScript. Страница задаёт начальную московскую дату на сервере; интерактивное расписание работает в клиентских компонентах. Запросы идут через `/api/*` того же origin к FastAPI. Браузер и Next.js не создают дополнительный кэш поверх бэкенда.

Упрощённая структура по мотивам FSD:

```text
frontend/
  app/                       # Маршруты, layout, метаданные, API route handler
  src/
    widgets/                 # Сборка экрана, состояние календаря, шапка
    features/                # Поиск группы, недели, подгруппы, обновление
    entities/schedule/       # Контракт, API-клиент, преобразования, карточка занятия
    shared/                  # HTTP, даты, настройки устройства, общие UI-элементы
  server.mjs                 # Запуск Next.js и лимит запросов по IP соединения
  tests/                     # Правила расписания, React-сценарии, прокси и лимиты
```

Импорты направлены вниз: `app → widgets → features → entities → shared`. Ограничения между слоями и порядок импортов проверяет ESLint: внешние, проектные, относительные, затем отделённый пустой строкой импорт стилей. CSS Modules (`*.module.css`) лежат рядом с UI: корень компонента — `.root`, дочерние элементы — по смыслу (`.list`, `.heading`). Компонент импортирует свой модуль как `s`; Next.js генерирует уникальные имена с именем модуля и хешем. Общие UI-компоненты лежат в `shared/ui/<name>/` со своим `index.ts` и импортируются через `@/shared/ui`; цветовые токены — в `shared/styles/tokens.css`, а в `app/globals.css` остаются reset и базовые стили. Глобального менеджера состояния нет: состояние календаря находится в одном React hook, локальное состояние поиска — в компоненте поиска.

Запускайте фронтенд через `npm run dev` / `npm start`. Небольшой Node.js entrypoint читает IP непосредственно из соединения перед обработкой Next.js; это сохраняет отдельные квоты посетителей без доверия к произвольному заголовку браузера. Используется обычная production-сборка и Node.js-сервер, без standalone-режима. Этот вариант предназначен для Docker/self-hosting; подробнее о механизме — в [документации Next.js](https://nextjs.org/docs/app/guides/custom-server).

### Превью ссылок и поисковые системы

Канонический адрес — https://schedule.sovngarde.ru; метаданные задаются в `frontend/src/shared/config/site.ts`. Next.js выдаёт Open Graph и Twitter Card в HTML, PNG-обложку `/opengraph-image` (1200×630), `/robots.txt` и `/sitemap.xml`. Обложка собирается локально при production build без внешних шрифтов и API. При смене домена обновите конфигурацию сайта и подпись на обложке, затем пересоберите фронтенд.

После деплоя проверьте исходный HTML и доступность изображения для внешних ботов. Мессенджеры могут сохранять старое превью; наличие метатегов не гарантирует обновление их кэша или доступ через заблокированный сетевой маршрут. В sitemap включена главная: выбранные группы хранятся в браузере и не являются отдельными индексируемыми страницами. Для Google Search Console / Яндекс Вебмастера можно отдельно подтвердить домен и отправить sitemap.

### Расчётная верхняя/нижняя неделя

Под датами выбранной недели показывается подсказка «Верхняя/Нижняя неделя · предположительно» с раскрывающимся пояснением и ссылкой на университет. Опорная дата и её тип заданы на бэкенде через `ACADEMIC_REFERENCE_DATE` и `ACADEMIC_REFERENCE_KIND`: 7 сентября 2026 — нижняя (подтверждено пользователем). Чередование считается по полным неделям с понедельника в обе стороны, независимо от календарного номера недели. API не подтверждает этот признак; после каникул/изменения учебного графика опору нужно сверить и при необходимости обновить с пересозданием backend-контейнера. Подсказка не фильтрует занятия и не меняет запросы расписания.
